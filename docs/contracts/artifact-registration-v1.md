# Artifact registration v1 — accepted T10 bounded adoption

## 1. Authority, ownership and useful outcome

Accepted under [ADR-0018](../decisions/0018-project-artifact-registration.md) for FEAT-ART-001 / MOD-ART. NukeGeng selected a private OCI/Docker Distribution registry and accepted the exact T10.1a–f design on 2026-10-25. This contract does not modify accepted target.read Resource Policy v1 or adopt all of proposed release-execution v1. Baseline main b70def19f69d460d4d9dcac099fa46a56978718d contains T09 Nomad/Kubernetes; ART has only OCIImageDigest and its original 48 Domain tests.

The deliverable is an immutable, project-owned artifact catalog: an authenticated user selects an approved registry/repository, supplies a digest and platform, obtains bounded registry evidence and records a stable artifact ID for a later release. Actor is the current local User, never a body-supplied principal/tenant. artifact.register and artifact.read are new exact-project permission adoption; neither implies the other. CI intake, signed provenance, tag resolution, image/layer pull, vulnerability/signature scanning, release/approval, deployment and background execution remain outside T10.

| Owner | Owns / supplies | Forbidden shortcut |
|---|---|---|
| ART | Artifact identity, verification facts, declarations, registration receipts and persistence | Reading IAM/TEN/PRJ/SEC tables or storing plaintext/provider bodies |
| IAM / TEN | Current session/principal; current organization/membership/exact project assignment/role definition | Role-name authorization, automatic grants or platform fallback |
| PRJ | Current active project identity → tenant and monotonic revision | Trusting tenantId in a request or a registry configuration as membership proof |
| SEC | Typed registry credential metadata, immutable revisions/heads, native lookup and secret lifetime | Reusing TargetId or inventory authority for an artifact |
| AUD / Host | Durable intent/outcome plus owner transaction, fair gate, clock/floor and caller-bound response | Independent commits of artifact and its audit; new review/workflow service |

NukeGeng is the accepted custodian for this exact ART/registry slice; this does not assign or implement the entire proposed module. Existing accepted ADRs, owner data and historical checkpoints retain their scope.

## 2. Immutable identity and declaration semantics

Artifact identity is the tuple (tenantId, projectId, registryId, repository, rootDigest, platform). IDs are server-generated nonempty GUIDs; tenant derives from current PRJ identity and agrees with current TEN authority. registryId denotes one private project/repository connection, not an independently usable host URL or a global registry permission. repository is exact lowercase OCI repository syntax, at most 255 ASCII bytes as a Kordra bound. Reject tags, URL/userinfo/query/fragment, percent encoding, backslash, empty/dot/traversal segments and whitespace; never lowercase/trim an invalid input into validity. The repository grammar is the OCI Distribution grammar; a bare name such as team/frontend selects a repository, not a local filesystem path.

rootDigest uses existing OCIImageDigest semantics: exact sha256:64 or sha512:128 lowercase hex. No algorithm substitution. platform has exactly os, architecture, variant: os=linux; architecture=amd64 or arm64; variant=null except arm64 may explicitly select v8. Null is an exact no-variant selection, not a wildcard or the machine's platform. Key encoding is canonical JSON, never ambiguous delimiter concatenation. Two different root digests or requested platforms are different artifacts even if their selected child/config digest agrees.

Stored immutable facts are artifactId, owner tuple, selectedManifestDigest/size/mediaType, configDigest/size, observed platform, verifierProfile=artifact-registry-v1, trusted verifiedAtUtc and createdAtUtc. Preserve root media type and root byte count too. No replacement of these facts after registration; content-address mismatch is an error, not an update. Store the verified bytes' identities and small interpreted facts only, never the raw manifest/config, config Env/labels, Authorization or provider error text.

Each registration may have a sourceClaim: null, or an object with exactly sourceRepository, sourceCommit, buildRef. sourceRepository is a logical lowercase ASCII slug/path, 1–128 characters using [a-z0-9._/-], with no empty/dot/traversal segments or scheme; it is not a URL to fetch. sourceCommit is exactly 40 or 64 lowercase hex characters. buildRef is null or 1–128 ASCII letters/digits/dot/underscore/hyphen. All keys are required when the object is present; unknown/duplicate keys reject. These are user declarations, bound to that registration/principal; never overwrite another declaration or contact a source/CI service. Absence is allowed and explicit.

Expose contentVerification=manifest_config_hash_verified, layerAvailability=not_checked and signatureVerification=not_checked. A registration's provenance is declared_unverified or not_supplied. Do not expose a broad verified/deployable flag, claim signed CI authenticity, layer availability/pull success, hardware compatibility or deploy approval. T11 must explicitly decide which verification/provenance level it accepts. No business event/outbox is published in T10; proposed artifact.registered.v1 is not silently adopted.

## 3. Registry trust and provider compatibility

Private stopped-installation configuration has schemaVersion=1, installationId and registries. Maximum file 64 KiB and 32 entries. Each entry has exactly tenantId, projectId, registryId, displayName, repository, apiOrigin, destinationIps, caCertificateDerBase64, serverSpkiSha256 and authMode. Reject missing/null/unknown/duplicate fields. displayName is 1–80 printable ASCII characters; all identity/normalization rules above apply. IDs and (tenantId, projectId, canonical apiOrigin, repository) are unique; no alias permitting two credential profiles for the same connection. Registry selectors do not carry new authority.

Use 1–8 unique explicit IPs, one private CA DER (at most 16 KiB) and one lowercase SHA-256 SPKI pin per entry. Follow T09's canonical origin rules: HTTPS only, ASCII lowercase host, no trailing dot, IDN, userinfo, query, fragment, path other than empty/root, ambiguous encodings or IPv6 zone. Canonicalize brackets/default 443 and mapped addresses; reject normalization that hides an invalid input. Private addresses may be approved, but loopback, link-local/metadata, multicast, unspecified and unconfigured destinations are forbidden in production. Resolve DNS with cancellation and connect only to an approved address; validate the actual connection address. DNS changes cannot widen the allowlist.

Pin a SHA-256 entry digest over compact UTF-8 JSON in this exact order: schemaVersion (1), installationId, tenantId, projectId, registryId, displayName, repository, apiOrigin, destinationIps, caCertificateDerSha256, serverSpkiSha256, authMode. Use lowercase D-form GUIDs, ordinal-sorted unique normalized IP strings, the CA DER hash instead of Base64, and explicit serializer/property order. Save the original file hash separately. authMode is exactly anonymous, basic or static-bearer. Nothing in the file is a password/token/reference ID. Load only when explicitly configured; missing configuration disables registry registration/selectors, without disabling historical artifact reads or T09. No startup DDL, credential lookup, registry access or hot reload. Restart invalidates old boot/session authority. Approval of this design does not authorize a real configuration/registry activation.

Private locators are KORDRA_ARTIFACT_REGISTRY_CONFIGURATION_FILE and KORDRA_ARTIFACT_REGISTRY_CONFIGURATION_SHA256. Both or neither must be supplied; require a regular private owner-controlled file and exact original-byte SHA-256 match before parsing, using the existing private-file custody rules. A malformed/partial locator or invalid configuration is a startup error, never a permissive empty fallback. With neither locator, new registration/selectors are disabled, while persisted catalog/status queries remain available under their current project checks.

Reuse the accepted private-PKI approach: TLS 1.2/1.3, hostname/IP SAN, validity and server-auth chain to the configured CA plus exact SPKI before sending auth bytes. No insecure TLS, OS-root fallback, online AIA/revocation/CRL/OCSP fetch or public origin fallback. Offline revocation remains a residual risk mitigated by stopped configuration/pin rotation; no stronger revocation guarantee is claimed. Loopback TLS synthetic fixtures use internal test-only construction, not a production bypass flag.

Use BCL SocketsHttpHandler/HttpClient with HTTP/1.1 exact, invocation-owned client/handler, zero pooled lifetime and Connection: close per logical request. Disable proxy, redirect, cookies, automatic decompression, ambient credentials and automatic retries. Reject unexpected Content-Encoding/partial responses; do not follow Location or descriptor URLs. No Docker CLI/daemon/config.json, shell, SDK, refresh token, token-service/challenge-realm exchange or anonymous/auth fallback. A registry requiring such a flow returns sanitized unavailable; direct static Bearer support does not prove a provider-issued PAT works as an access token. No specific Harbor/GHCR/Docker Hub compatibility is claimed without its exact conformance proof.

## 4. Typed SEC seam and shared native credential boundary

For authenticated modes, SEC must supply RegistryCredentialSelectionV1(installationId, tenantId, projectId, registryId, repository, consumerId, operation). consumerId is exactly artifact.registry.read.v1; operation is artifact.register. Selection, active profile/reference/current binding revisions, expiry/revocation and entry configuration digest must match U, C and M. Anonymous mode uses the same current authority stages but no reference, native helper or dummy secret. Configuration chooses the mode; a failed authenticated read never tries anonymous.

Add typed registry profiles/references/binding history/current heads/command receipts inside the existing SEC module and context. Additive immutable revision/history and offline apply/rotate/revoke rules match T08, but validation uses exact project/registry/repository identity. One current binding per exact selection. SchemaVersion=1 for the new registry snapshots/offline manifest; do not extend legacy positional records or reserialize inventory v1/v2 hashes. Inventory constructors, tables' meaning, TargetId semantics, consumers and reference/binding digest bytes remain unchanged.

The helper selects native identity by installationId/referenceId. Introduce a neutral SEC reference-allocation relation keyed by that pair, with tenantId and exactly one inventoryProfileId or registryProfileId, explicit owner-kind check and owner FK. A reference's kind/profile/tenant cannot change or be reused after revoke. Legacy inventory and new registry reference writers allocate and link in the same transaction; references FK to their exact allocation. Backfill existing inventory metadata only; never inspect Keychain to infer ownership. Migration must stop rather than resolve conflicting/invalid data by guessing. Keep allocation rows on rollback/revoke. An older writer which cannot maintain allocations is unsupported for credential mutations; do not leave it enabled alongside the new writer.

Add a typed overload to the existing CredentialBroker/Reservation, sharing the same native lookup implementation, helper protocol and two helper slots. No separate broker/service/pool. Await confirmed helper exit before slot release/C; unproved quiescence fences admission as today. Both legacy and registry paths must pass regression tests. Profile creation/rotation cannot share an existing inventory reference through caller-chosen IDs or a foreign allocation.

The consumer receives invocation-borrowed opaque bytes only after confirmed U/helper exit/current C. Basic interprets strict UTF-8 username:password, splitting the first colon: both parts nonempty, username contains no colon, no NUL/CR/LF/control characters; total at most the existing 16 KiB secret bound. static-bearer accepts 1–4096 ASCII bytes using the existing T09 bearer-token grammar. Invalid bytes fail without logging/copying into an error. anonymous receives no secret bytes. Do not return plaintext through ART/SEC public Contracts or HTTP.

An independently authorized operator provisions a repository-read credential, never registry administration/write/delete authority. A registry's pull scope can also permit layer reads; Kordra still calls only this contract's manifest/config allowlist. Binding proves current credential selection, not that the registry token's own effective server grants have been inspected. New typed offline manifests retain T08's stopped-API OS-lease/plan-hash controls and explicit new reference allocation; they cannot select a legacy inventory reference or create a default registry credential.

Accepted narrow exception to T08's default managed-plaintext prohibition is only the necessary post-C Basic encoding/Bearer Authorization on each approved request. The request header is never DefaultRequestHeaders, a retained token field, cookie, URI or log; dispose request/response and clear owned mutable buffers after use/cancellation. Framework strings/header memory are not deterministically erasable. HTTP diagnostics/exporters must not capture headers/bodies; new instrumentation needs review. No secret file fallback or existing Keychain read is authorized by adopting this contract.

## 5. Bounded image verifier

Only GET these fixed paths, with the configured origin/repository and validated digest: /v2/{repository}/manifests/{rootDigest}; optionally /v2/{repository}/manifests/{selectedChildDigest}; /v2/{repository}/blobs/{configDigest}. At most three logical requests and zero transport/application retries. Never query catalog/tags, resolve a tag, use HEAD as content proof, download layers or follow descriptor urls. Accept only 200 with an allowed media type; safe reason codes replace raw headers/body on every error.

Support OCI image manifest/index v1 and Docker schema-2 manifest/manifest-list media types. schemaVersion must be 2. Root and selected child must be actual image manifests/indexes within this profile, not OCI artifact/referrer content. Hash exact raw response bytes before interpreting JSON. Root must match the requested digest; selected child/config must match descriptor digest and exact declared byte size. Header Docker-Content-Digest, if present, must itself verify against the body; a different supported SHA algorithm is allowed, never substituted for requested identity. A missing digest header is allowed. Manifest descriptor/response Content-Type/body mediaType must agree where present; parse bounded Content-Type parameters without treating them as a different type. Unsupported algorithms, duplicate interpreted keys, malformed/too-deep JSON, zero/oversize descriptor sizes, missing config or hash/size mismatch reject.

For config blobs, interpretation comes from the verified manifest's OCI/Docker config descriptor, not a requirement that the blob HTTP header repeats that type. Accept the descriptor's config media type, application/octet-stream or application/json on the fixed blob GET, then verify size/hash and parse bounded config JSON. Generic octet-stream is normal for the [Distribution blob endpoint](https://distribution.github.io/distribution/spec/api/); it is never accepted as a manifest Content-Type or permission to fetch another blob. Missing/other Content-Type is outside this initial profile. Pin octet-stream config and SHA-512-request/SHA-256-header cases in ART10-05.

An index/list has at most 32 descriptors. Select exactly one descriptor with the exact requested platform tuple; zero or multiple matches reject, never first-match or host-platform fallback. Unknown non-selected media types/extensions may be ignored within parser/count limits. A selected nested index, unsupported OS constraints or non-image media type rejects. The selected manifest config must agree on os/architecture; a present config variant must match. A null variant selection requires no descriptor/config variant; v8 may rely on an exact index descriptor if config omits variant, recorded as descriptor-asserted. For a single root manifest, v8 requires explicit config variant. Never infer v8 or runtime compatibility from arm64 alone. Pin acceptance vectors for both successful and rejected cases.

Validate config against OCI/Docker image config media types and retain only platform facts. Parse at most 128 layer descriptors and retain no layer body or registry URLs; their digest syntax/size is validated but existence is not. An external urls field is never a fetch destination. Unknown config fields/annotations/Env/labels are bounded untrusted JSON, not disclosures or additional behavior. Do not serialize a raw JsonElement into an API result.

Kordra bounds: one-second deadline per logical request including DNS/connect/TLS/body; at most 1 MiB per document, 3 MiB total, 16 KiB response headers, JSON depth 32. Enforce streaming byte counts even without Content-Length; reject oversized declared lengths before reading. Keep existing ten-second invocation/five-second-from-U budgets, two-second helper plus 500 ms cleanup and shared capacity. The minimum remaining budget wins; cancellation cannot create an unobserved retry/helper. Capture trusted verifiedAtUtc; verifier private result expires at capture + 15 seconds, capped by original/current authority/SEC/invocation deadlines. No provider timestamp extends it.

Existing offline definition/assignment machinery explicitly provisions the new actions under current grantor limits. Add PRJ-owned IProjectIdentityReader.ReadCurrentProjectUnderAdmissionAsync(projectId) returning active tenant/project/revision or no usable fact; it is not a body-tenant lookup or new ART table access.

IAM's fixed artifact-registration-v1 predicate requires current boot/session, active principal, active tenant/organization and membership, exactly applicable current project assignment/definition, requested action Allow with no matching Deny, active PRJ project and exact configured connection tenant/project/repository where needed. No organization/platform/inventory grant inheritance, generic new policy engine, synthetic environment or TargetId. Missing/unavailable/conflicting facts deny. Read/status/list predicates have the same project ownership/permission rules but no unnecessary provider/SEC prerequisite.

Host supplies current owner adapters under the existing fair gate; ART never authorizes itself. Bind an internal v1 authority digest with a domain separator to invocationId, boot/session/principal identity and revisions, tenant/project/revision, exact assignment/membership/organization/role-definition identities/revisions, action, registry entry digest and SEC selection/revisions when applicable, plus original expiry. C, M and D must see the same identity/revisions and still-valid current facts; replacement then restoration is a change. Minimum original/current expiry applies. Clock floor/audit sequence advances from this invocation are not authority revisions. Pin explicit canonical vectors; old inventory serializers are untouched.

Share the existing sixteen protected invocation slots across inventory and artifacts. A narrow extraction of their capacity holder into the existing Security assembly is permitted; do not instantiate a second sixteen-slot gate or general authorization framework. Authenticated registration also reserves one of the same two SEC helper slots. Hold invocation ownership through completion/cleanup; release permits only after known quiescence. T09 behavior must remain unchanged under shared saturation.

| Stage | Lock/current checks and durable evidence | Permitted work afterwards |
|---|---|---|
| U | Reserve capacity; under shared writer gate resolve current exact project/registry/SEC authority, validate idempotency, atomically persist Pending receipt + AUD Use + clock floor | Release DB transaction/gate, then one bounded credential lookup if needed |
| C | After confirmed helper exit, under shared read gate recheck same facts/expiry and persist AUD Use with safeReason identifying C | Release gate; bounded fixed-origin registry GETs; no auth/network before C |
| M | Under shared writer gate recheck facts, verifier freshness, exact Pending/boot/business identity; transactionally resolve artifact identity and persist terminal result/claim + AUD Mutation + floor | Release transaction/gate; no remote call while held |
| D | Recheck same current caller/owner/grant and safe result binding, durable AUD Disclosure, existing pre-header caller-bound commitment/expiry | Disclose only bounded sanitized result; no reusable permit |

Reuse AUD schemaVersion=1 and Use/Disclosure/Mutation/Outcome stages; U/C have distinct nonsecret safe reasons/context hashes. Action artifact.register or artifact.read and project scope are explicit. Include invocation/registration/artifact/owner refs and canonical command/result hashes, never plaintext/private origin or raw provider text. U permits record eligibility/intention only; they do not prove registry success. Read/list/status uses query-specific U/D and candidate-set hash, not an inventory ProtectedReadPlan/permit. Registration IDs, artifact IDs and rows must belong to the current project before any result is emitted.

Any revocation, expiry, scope/role/profile/reference/config change between stages withholds further provider use, mutation or disclosure as appropriate. A committed artifact can remain if permission is revoked before D; withhold the body and do not roll back a confirmed owner transaction. A later read/replay obtains fresh authority. Unknown commit outcome fences shared admission only after a commit was actually attempted; setup/enlistment/pre-commit cancellation failure is a known no-commit path and must not poison the host. Preserve T03's regression.

## 7. Durable idempotency and interrupted recovery

Require Idempotency-Key: 16–128 ASCII letters/digits/dot/underscore/hyphen. Store a domain-separated SHA-256 key hash scoped to installation/tenant/project/principal/action; never log the raw key. Canonical business input is schemaVersion, trusted project/tenant, registryId, repository, rootDigest, requested platform, sourceClaim in that order with explicit nulls and fixed nested field order. Exclude correlationId, the header key and mutable current grants. Store its domain-separated SHA-256 alongside the key. Identical key with different business input is 409 without a provider call, including after crash. Current authenticated project authority is required before receipt lookup/disclosure; a key is not a capability.

Registration state is Pending → Registered, Failed or Abandoned only. Persist server-generated registrationId, current boot/invocation, initiator/project identity, business/key hashes, timestamps and U references before any external use. Exactly one attempt owns a Pending receipt. Same-body replay of Pending returns 409 registration_in_progress with its current-authorized own receipt/registrationId so status can be inspected; no second helper/provider execution, 202/background survival promise or automatic takeover. Terminal Registered replay returns its stored immutable result after fresh D/current artifact.register; Failed/Abandoned replay returns the terminal safe outcome. A new attempt after terminal failure requires a new explicit key.

Replay/status starts a fresh query-specific U/D with current project/session/grant evidence, not the old permit or expiry. It does not create another Pending, C/M stage or provider call; a removed registry configuration/binding does not hide an otherwise authorized historical receipt. Only a new registration attempt needs current configured connection/SEC facts. Never use receipt existence to bypass current principal/project checks or to grant artifact.read.

At M, a unique database identity constraint on the artifact tuple ensures one artifact despite competing distinct keys. Check/update only the current receipt; attach each registration's own declaration and reference the existing artifact when immutable content/platform/media-type/size/profile facts agree. Do not compare new attempt timestamps/declarations to the first artifact's timestamps/declarations as if those were a content conflict. Preserve the artifact's first createdAtUtc/verifiedAtUtc; save this attempt's actual verification time on its own receipt. Do not overwrite another declaration or borrow another principal's result receipt. Known unique-conflict rollback may do one fresh-authority local reconciliation to the same matching artifact, with no new HTTP; unresolved conflict/fact disagreement is a safe failure requiring investigation. All artifact/receipt/declaration/AUD/floor changes commit once on the same connection/transaction. Database loss/ACK uncertainty returns no success/body and fences; a mutable in-memory outcome cannot stand in for durable evidence.

Known failures after confirmed U attempt an exact-invocation Pending→Failed bookkeeping transaction plus AUD Outcome/floor, with no artifact creation or new provider use. This trusted terminalization may record a revoked caller's failure without granting that caller new business authority. If it cannot finish, retain Pending; do not claim the attempt is terminal. A commit attempt with unknown outcome follows fencing, not a guessed Failed transition. Pre-U rejection creates no registration. Bound cancellation/timeout cleanup; never claim exactly-once wire GETs.

Recovery is an offline stopped-API owner command with the installation OS lease and a reviewed exact registration/boot plan. Read authoritative ART/AUD receipts; require proof the old process/helper is quiescent. Confirmed Registered remains Registered. Confirmed Pending with no M commit may become Abandoned with audit/floor, allowing a separate explicitly keyed attempt later. Missing/ambiguous transaction/receipt evidence stays fenced. Never create an artifact, replace a result/declaration, reuse a key, read a credential or contact the registry in recovery. No automatic replay on restart; existing stopped-installation enrollment/session rules remain. A reused registration result is a recorded historical verification, not a fresh registry availability proof.

## 8. HTTP surface and disclosure

All routes use existing local HTTPS/session/no-store/caller-bound response rules. POST requires exact same-origin/CSRF and strict framing/body handling; body at most 16 KiB. Unknown/duplicate fields, unsupported schemaVersion, conflicting content length/transfer encoding or extra query keys reject. No tenant, endpoint, credential, policy, selected child/config digest or caller-chosen record ID is accepted as authority.

correlationId is a nonempty canonical D-form GUID, used for diagnostics only. Define strict v1 success envelopes: detail has schemaVersion/correlationId/artifact; registration/status has schemaVersion/correlationId/registration; lists have schemaVersion/correlationId/items/nextAfterArtifactId (nullable); selectors have schemaVersion/correlationId/items. A list cursor is absent/null only on the final page; it does not attest that no new rows can appear later.

| Route | Permission and contract |
|---|---|
| POST /api/v1/projects/{projectId}/artifacts | artifact.register. Exactly schemaVersion (1), correlationId, registryId, repository, digest, platform, sourceClaim; Idempotency-Key required. Server selection/verification supplies the rest. 201 for first confirmed registration, 200 for authorized Registered replay; both include own registrationId, immutable artifact projection and own declared/not_supplied provenance. A new key resolving an existing artifact is a new 201 registration, not a rewritten artifact. |
| GET /api/v1/projects/{projectId}/artifacts/{artifactId} | artifact.read; current project, immutable detailed facts, no other registration's declaration or private registry/binding values. No provider call. |
| GET /api/v1/projects/{projectId}/artifacts?limit=…&afterArtifactId=… | artifact.read; default/max 50, minimum 1; bounded projection id/registryId/repository/rootDigest/platform/createdAtUtc/contentVerification. Ordered by createdAtUtc then artifactId, both ascending. Cursor is an existing artifact in this authorized project, not a scope token. Fresh authorization on every page; candidate IDs/hash bound at U/D. No cross-page atomic-snapshot/total-count guarantee. |
| GET /api/v1/projects/{projectId}/artifact-registrations/{registrationId} | artifact.register AND same current principal as initiator; safe Pending/Registered/Failed/Abandoned state and only its result/claim. No provider call or cross-user receipt lookup. |
| GET /api/v1/projects/{projectId}/artifact-registries | artifact.register; at most 32 configured selectors, only registryId/displayName/repository/authRequired. No origin/IP/CA/pin/profile/reference/credential or implicit connectivity/readiness claim. No provider call. |

Wire schemaVersion=1 is new, not a change to metadata/environment/inventory responses. GUIDs are canonical strings, dates UTC; platform and digest retain exact semantics. Detail/registration results are at most 16 KiB, list at most 64 KiB; never truncate into a partial success. Candidate sets/results are private and bound to query/principal/project/expiry. Historical catalog reads do not require a current registry connection, credential or current provider availability. They still require current project authority. First registration's verifiedAtUtc never becomes a current observation timestamp by replaying it.

The detailed artifact projection has exactly artifactId, projectId, registryId, repository, rootDigest, platform, rootMediaType, rootSizeBytes, selectedManifestDigest, selectedManifestSizeBytes, selectedManifestMediaType, configDigest, configSizeBytes, observedPlatform, variantEvidence, verifierProfile, verifiedAtUtc, createdAtUtc, contentVerification, layerAvailability and signatureVerification. variantEvidence is none/config/descriptor; config is used when a matching variant was actually present in config, descriptor only for the explicitly allowed missing-config-variant index case. A registration projection has exactly registrationId, status, createdAtUtc, completedAtUtc (nullable), attemptVerifiedAtUtc (nullable), safeReason (nullable), artifact (nullable), sourceClaim and provenance. Artifact/attemptVerifiedAtUtc are present only for Registered; only its own claim is returned. List/selector projections are the exact fields in the route table. No owner-internal raw record serialization is allowed. GET correlationId is server-generated; POST responses bind the validated request correlationId.

Use 400 for invalid request shape/value and 413 for body limits; 401 for absent/invalid session; 403 for current authority denial; 404 only for absent/out-of-project records after project authorization; 409 for key/body conflict or Pending; 422 for an authorized but unsupported/mismatching image selection; 503 for capacity/store/audit/provider/unknown outcome. Failed/Abandoned key replay returns 409 registration_terminal with its current-authorized safe receipt, rather than retrying it. Return bounded fixed safe codes and correlationId; no raw network exception, provider 401 body, secret, private endpoint or distinguishable foreign receipt detail. Pending/terminal status cannot be used to enumerate foreign records. Cancellation before/after headers follows the existing commitment/abort boundary; no body after an invalid D.

Error envelopes have exactly schemaVersion/correlationId/code/registration (nullable). Only same-body current-authorized Pending/terminal replay includes its own safe registration; key conflicts and other errors leave it null. Store/result uncertainty emits no receipt/artifact body. Page queries fetch at most limit+1 (51) candidates to determine a next cursor, return at most limit items, and bind that bounded selection to disclosure; a cursor is not a promise about future inserts.

## 9. Persistence, migration and dependency compatibility

ART owns app.art_artifacts, app.art_registration_receipts and app.art_provenance_claims, plus its own art_ef_migrations_history. Immutable artifact tuple/facts/claims and registration business identity have database uniqueness/FK/immutability guards; receipts allow only Pending→terminal changes to outcome fields. Every claim FK includes tenant/project/artifact and its own registration; prevent foreign tenant/project linkage at SQL and application boundaries. Preserve record IDs, first timestamps and allocations through duplicates/recovery. No deletion/GC/retention purge command is adopted.

Reuse already locked EF Core 10.0.11/Npgsql 10.0.3 for the new ART store only; BCL networking/JSON, no provider SDK. No Marten/Wolverine, hosted worker, new shared kernel or startup migration. New projects after acceptance: src/Modules/ArtifactManagement/Contracts/Kordra.Modules.ArtifactManagement.Contracts.csproj (BCL-only), src/Modules/ArtifactManagement/Kordra.Modules.ArtifactManagement.csproj (runtime), tests/ArtifactManagement.Tests/ArtifactManagement.Tests.csproj. Keep existing Domain/test projects/names unchanged; runtime excludes Domain/Contracts source globs and references only own Domain/Contracts. Host references the required owner Contracts and composes their current-authority adapters; ART does not acquire cross-owner implementation dependencies or read their tables.

DbMigrator supplies an offline ART migration command using KORDRA_ARTIFACT_MIGRATION_CONNECTION_STRING and existing role/loopback/installation guards; runtime locator is KORDRA_ARTIFACT_CONNECTION_STRING. Match spellings in source/runbook/regression; no migration on startup. Offline configuration/binding/recovery extends the existing grouped Host commands, with exact plan inspection/apply, OS lease and stopped API, not a generic public administration API. New runtime ART DB permissions are minimum DML needed for its guarded writes, with no DDL or unrestricted artifact/claim updates/deletes; migrations use kordra_admin, integration tests only isolated kordra_test. Do not execute real-installation migrations from design acceptance.

ART and shared transactional owners must resolve to the same approved loopback installation/database/runtime role; validate locators before enabling composition. Host supplies their one connection/transaction, never a distributed/independently committed ART store. Minimum ART/SEC schema-version checks must be satisfied before writes; no partial compatible-looking activation or permission repair at API startup. No real-installation probe/migration authority is added by these requirements.

SEC's additive allocation/registry migration must backfill metadata, enforce cross-kind uniqueness/FKs, preserve existing rows/digests, test partial failure/rollback, and keep existing inventory reads valid. Rollback disables registration/config and compatible new writers before code/schema rollback; never destructive Down, allocation deletion, revoked-head restoration or writer downgrade which breaks uniqueness. ## T10.1a implementation details — 2026-10-25

The accepted v1 identity/business encoding is implemented with compact UTF-8 JSON, explicit property order and nulls. Identity/business fields are schemaVersion, projectId, tenantId, registryId, repository, rootDigest, platform, then sourceClaim for business input. Platform is os/architecture/variant; claim is sourceRepository/sourceCommit/buildRef. Domain separators are artifact-identity-v1, artifact-registration-request-v1 and artifact-registration-key-v1, each followed by one LF before JSON. Key fields are schemaVersion, installationId, tenantId, projectId, principalId, action (artifact.register), key. Correlation, boot and receipt IDs never change business identity. The source's independent Python-derived golden vectors pin these bytes; no old inventory/SEC serialization is changed.

Owner store methods return staged results only and require the caller transaction.
